## Outline

- **The commit message as a genre:** conventions (Conventional Commits, Angular, kernel style) and what choosing one says about a team
- **The information hierarchy:** subject line, body, trailers, co-authors
- **What terse messages mean:** velocity, solo work, exhaustion, or indifference?
- **Case study: the Linux kernel** — Torvalds's merge-commit messages as editorial commentary on other people's code
- **The `Signed-off-by` trailer and the Developer Certificate of Origin:** provenance tracking as archaeological metadata
- **What commit messages cannot tell you:** the conversation that happened before the code was written
