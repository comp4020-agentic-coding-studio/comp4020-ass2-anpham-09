# What the docs do not say

SLOP2374 · Week 6

---

## The documentation hierarchy

- README
- API documentation
- Inline comments
- Wikis, changelogs, issue templates

Each layer rots at a different rate. That difference is the evidence.

---

## Rates of decay

Inline comments rot first — they sit next to code that changes without them.

READMEs rot slowly, because they are read.

Changelogs stop rather than rot. The date they stop is a date worth having.

---

## The README paradox

The most visible document in any project is the one most likely to describe a
version that no longer exists.

It is written once, at the moment of most enthusiasm, and revised least.

---

## Reading the gap

- README accurate, comments stale → **died recently**
- README promises features the code lacks → **died slowly**
- No documentation at all → the audience was always one person

The gap between promise and behaviour is the most diagnostic artefact on any
dig site.

---

## Case study: GeoCities

In 2009 Yahoo deleted roughly 38 million user-built pages.

The Archive Team scraped what they could in the months before shutdown. What
survived is what volunteers happened to reach in time.

Preservation is not a property of the artefact. It is an act someone performs.

---

## The undocumented behaviour

Every mature codebase does something nobody wrote down.

Find one on your dig site. Ask why it went undocumented — obvious, embarrassing,
or added by someone who assumed they would be around to explain it?
